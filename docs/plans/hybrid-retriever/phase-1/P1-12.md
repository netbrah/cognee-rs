# P1-12 — Documentation updates

## Goal

Bring the five documentation surfaces that describe the search subsystem
current with the `HYBRID_COMPLETION` port: the crate/architecture inventory,
the operations overview, the configuration reference, the CLI reference, and
the HTTP `search` router spec. This is the doc-only closeout task for Phase 1
of the hybrid-retriever port — per `.claude/CLAUDE.md`'s "keep docs current"
mandate, no other task in this phase touches these five files, so without this
task they drift the moment `SearchType::HybridCompletion` ships. It also
carries the one required "Known limitations" note so downstream integrators
(HTTP clients, other SDK ports) know exactly which knobs are wire-accepted but
functionally inert or degraded in Phase 1.

        the `uuid5(chunk_id, "TextSummary")` id-derivation fallback once that

## Parity notes

Exact constants/formulas/citations to carry into the docs verbatim (already
locked decisions for the implementation tasks; this task only needs to *cite*
them correctly, not re-derive them):

- **BM25**: Okapi BM25, `k1=1.5`, `b=0.75`
  (`/tmp/cognee-python/cognee/modules/retrieval/bm25_retriever.py:18-24`).
  IDF: `ln(1 + (N - df + 0.5) / (df + 0.5))` (`bm25_retriever.py:83-85`).
  Score: `Σ over unique query terms of idf(t) * (tf(t) * (k1+1)) / (tf(t) + k1*(1 - b + b*|chunk|/avg_len))`
  (`bm25_retriever.py:87-103`). Stop words: `DEFAULT_STOP_WORDS`
  (`/tmp/cognee-python/cognee/modules/retrieval/utils/stop_words.py:4`). This
  is **not** the existing Rust `LexicalRetriever`'s multiset-Jaccard scorer
  (`crates/search/src/retrievers/lexical_retriever.rs`) — a separate BM25
  lane, per-query corpus rebuild (no `OnceCell` reuse — contrast with
  `LexicalRetriever`'s `cached_chunks: OnceCell<Vec<CachedChunk>>` at
  `crates/search/src/retrievers/lexical_retriever.rs:29`, which is
  process-lifetime and intentionally *not* the pattern BM25 follows).
- **Batched neighborhood**: Python calls
  `graph_engine.get_neighborhood(entity_ids, depth=1)`
  (`/tmp/cognee-python/cognee/modules/retrieval/hybrid/entities.py:31`). The
  Rust `GraphDBTrait` addition must return true stored edge direction (not
  `get_connections`'s bidirectional-pattern treatment — see
  `crates/graph/src/ladybug.rs:2040-2070`'s "add both directions" test, which
  is exactly the flip this fixes).
- **`source_chunk_id` / uuid5 fallback**: node filter on summary hits reads
  `summary_payload.get("source_chunk_id")` and skips the summary-rank slot
  with a warning if absent
  (`/tmp/cognee-python/cognee/modules/retrieval/hybrid/pairs.py:44-51`); the
  id-derivation fallback that still recovers summary text is
  `uuid5(chunk_uuid, "TextSummary")`
  (`/tmp/cognee-python/cognee/modules/retrieval/hybrid/pairs.py:91-96`), used
  by `load_summary_text_for_ranked_pairs`
  (`/tmp/cognee-python/cognee/modules/retrieval/hybrid/chunks.py:212-230`).
- **`belongs_to_set` node filter**: a missing/non-list `belongs_to_set` on the
  payload makes `payload_matches_node_filter` return `False` whenever
  `node_name` is non-empty
  (`/tmp/cognee-python/cognee/modules/retrieval/hybrid/results.py:39-51`) —
  this is the exact mechanism behind the entity-search-returns-empty
  limitation, cited above.
- **`importance_weight` neutral default**: `DataPoint.feedback_weight`
  already defaults to `0.5` via `default_feedback_weight()`
  (`crates/models/src/data_point.rs:11-14`) — the new `importance_weight`
  field (landed by an earlier task in this phase, not P1-12) is expected to
  follow the identical `Option<f64>` + neutral-default pattern; confirm this
  at doc-edit time by reading `crates/models/src/data_point.rs` fresh (do not
  assume the field exists yet — as of this writing `importance_weight` lives
  only on `Data`/`DataPoint`'s ingestion-side sibling `crates/models/src/data.rs:58`,
  not yet on `DataPoint` itself; that migration is tracked by an earlier task
  in this phase, not this one).
- **Global context util absence**: Python's global-context lane depends on
  `get_memory_fragment` + a `GlobalContextSummary` node type
  (`/tmp/cognee-python/cognee/modules/retrieval/utils/global_context.py:1-53`);
  no Rust equivalent exists as of this writing (grep
  `crates/search/src/ crates/graph/src/` for `GlobalContextSummary` to
  reconfirm at execution time — it should still return zero hits until that
  util is ported).
