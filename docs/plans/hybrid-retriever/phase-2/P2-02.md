# P2-02 — Truth-subspace: centroid slot logic

## Goal

Port the pure, deterministic centroid-slot maths from Python's
`cognee/modules/truth_subspace/centroids.py` and `models.py` into
`crates/truth-subspace`: the `TruthCentroidPayload` model and the functions
that derive centroid/learning ids, normalize/pad vectors, merge
running-mean centroids, and assign new learning statements to the nearest
slot. This is the deterministic core the deferred Phase-2 build pipeline
(`build_truth_subspace`, task P2-03) will drive; it has no I/O and no
vector-engine dependency, so it is fully unit-testable now even though
nothing calls it yet (`use_truth_weight`/`build_truth_subspace` stay
default-off per the locked Phase-2 decisions).

## Implementation steps

1. **`TruthCentroidPayload`** (`models.rs`). Port `models.py:5-12` as a
   plain struct — not a `DataPoint` subclass (Python's model is a bare
   pydantic `BaseModel`):
   ```
   pub struct TruthCentroidPayload {
       pub dataset_id: String,
       pub slot: usize,
       pub count: usize,
       pub truth_epoch: i64,
       pub updated_at: i64,
       pub centroid: Vec<f64>,
       pub learning_ids: Vec<String>,
   }
   ```
   Derive `Debug, Clone, PartialEq, Serialize, Deserialize`. `slot`/`count`
   narrow Python's unbounded `int` to `usize` (always non-negative here);
   keep `truth_epoch` as `i64` (permissive, matches how the deferred build
   task mints epochs). `learning_ids` defaults to `Vec::new()` via
   `#[serde(default)]`, mirroring `Field(default_factory=list)`
   (`models.py:12`).

2. **Constants** (`constants.rs`, skip if P2-01 already added it). Port
   `constants.py:1-7`: `pub const DEFAULT_K: usize = 8;`. Python's
   `TRUTH_CENTROID_COLLECTION = "TruthCentroid_vector"` is one string
   because Python's vector API takes a single collection name; Rust's
   `VectorDBTrait` always takes a `(data_type, field_name)` pair and
   derives the physical name as `format!("{data_type}_{field_name}")`
   internally (`crates/vector/src/brute_force_vector_db.rs:59-60`,
   `crates/vector/src/lancedb_adapter.rs:43-44`,
   `crates/vector/src/pgvector_adapter.rs:167`). So the Rust constant is
   the pair: `pub const TRUTH_CENTROID_COLLECTION: (&str, &str) =
   ("TruthCentroid", "vector");` — reconstructs to Python's exact string.
   Not used for I/O in this task; P2-03 (`load_centroids`/`upsert_centroids`
   port) will destructure it for `vector_engine` calls. `TRUTH_NODE_SET`/
   `truth_session_node_set` (`constants.py:2,6-7`) belong to the graph
   nodeset-query path used by `build.py` — out of scope here, port in P2-03.

3. **`centroid_id`**. Port `centroids.py:20-21`:
   `uuid5(NAMESPACE_OID, f"TruthCentroid:{dataset_id}:{slot}")` →
   `Uuid::new_v5(&Uuid::NAMESPACE_OID, format!("TruthCentroid:{dataset_id}:{slot}").as_bytes())`.
   Use `Uuid::NAMESPACE_OID` or `cognee_utils::NAMESPACE_OID` (byte-identical
   per `crates/utils/src/id_generation.rs:14-16`) directly — **do not**
   route through `cognee_utils::data_point_id_for`. Verified divergence:
   `data_point_id_for` (`crates/utils/src/id_generation.rs:81-88`) runs
   every value through `normalize_identifier` (lowercase, spaces → `_`,
   apostrophes stripped) before `|`-joining and hashing
   `"{class_name}:{joined}"`; Python's `centroid_id` does no normalization
   at all and joins two values with `:`, not `|`. The two schemes are not
   equivalent in general, so use a raw `Uuid::new_v5` call with the exact
   Python format string.

4. **`learning_id`**. Port `centroids.py:24-26,197-198`:
   ```rust
   pub fn learning_id(statement: &str) -> String {
       let normalized = statement.to_lowercase().split_whitespace().collect::<Vec<_>>().join(" ");
       Uuid::new_v5(&Uuid::NAMESPACE_OID, format!("TruthLearning:{normalized}").as_bytes()).to_string()
   }
   ```
   Python's `_normalize_statement` uses `str.casefold()`
   (`centroids.py:198`), stricter than Rust `.to_lowercase()` for some
   Unicode (e.g. German ß). Accept as a documented divergence for
   non-ASCII input under the structural-parity bar — no new dependency for
   this. Return type is `String` (Python returns `str(uuid5(...))`), not
   `Uuid` — `learning_ids: Vec<String>` stores it as text.

5. **`normalize`** (L2). Port `centroids.py:29-34`: `norm =
   sqrt(sum(v*v))`; if `norm == 0.0` return a same-length all-zero vector
   (no panic/NaN). `pub fn normalize(vector: &[f64]) -> Vec<f64>`.

6. **`pad_coords`**. Port `centroids.py:37-39`: front-truncate to at most
   `k` values, then zero-pad on the right to length `k`. `pub fn
   pad_coords(coords: &[f64], k: usize) -> Vec<f64>` — Rust has no
   default-arg sugar, so require `k` explicitly at call sites (matching
   how the build/extend functions below also take `k` explicitly).

7. **`weighted_centroid`**. Port `centroids.py:42-52`: if `old` is empty,
   return `normalize(new)`; else `safe_count = max(0, count)`, merge each
   paired component as `(safe_count*old + new) / (safe_count+1)`, then
   `normalize` the result. Zip-truncates to the shorter input (Python
   `zip` semantics) — don't pad/error on length mismatch.

8. **`unique_learning_vectors`**. Port `centroids.py:55-64`: iterate
   `(statement, vector)` pairs, skip statements empty after `.strip()`,
   key a map by `learning_id(statement)` keeping the **first** vector seen
   per id (`HashMap::entry(...).or_insert_with(...)`, matching
   `dict.setdefault`), then return items **sorted by the id string**
   (`centroids.py:64`), not insertion order. `pub fn
   unique_learning_vectors(statements: &[String], vectors: &[Vec<f64>]) ->
   Vec<(String, Vec<f64>)>`; zip-truncates like Python.

9. **`build_centroids_from_learning_vectors`**. Port `centroids.py:67-81`
   as a thin wrapper calling `extend_centroids_with_learning_vectors` with
   an empty `existing_centroids` slice:
   ```rust
   pub fn build_centroids_from_learning_vectors(
       dataset_id: &str,
       learning_vectors: &[(String, Vec<f64>)],
       truth_epoch: i64,
       updated_at: Option<i64>,
       k: usize,
   ) -> Vec<TruthCentroidPayload>
   ```

10. **`extend_centroids_with_learning_vectors`** (core slot-assignment).
    Port `centroids.py:84-137`:
    - Resolve `updated_at`: if `None`, `chrono::Utc::now().timestamp_millis()`
      (matches `datetime.now(timezone.utc).timestamp() * 1000`,
      `centroids.py:93`, modulo sub-millisecond float rounding — immaterial).
    - Build `slots: Vec<{centroid: Vec<f64>, count: usize, learning_ids:
      Vec<String>}>` from `existing_centroids` **sorted by `.slot`**,
      truncated to `k` entries (`centroids.py:101`) — silently drops any
      slot `>= k` from a stale higher-`k` run; intentional, matches Python.
    - Collect `seen_learning_ids: HashSet<String>` from every slot's
      `learning_ids` (`centroids.py:103`).
    - For each `(new_learning_id, vector)` in `learning_vectors`, **in the
      caller's given order** (this loop does not run over
      `unique_learning_vectors`'s sorted output — callers dedupe first if
      they want that):
      - Skip if already `seen` (`centroids.py:106-107`).
      - L2-normalize the vector (`centroids.py:108`).
      - If `slots.len() < k`: append a new slot `{centroid:
        normalized_vector, count: 1, learning_ids: vec![new_learning_id]}`
        (`centroids.py:109-113`) — first `k` distinct ids each get their
        own slot, in first-seen order.
      - Else: find the nearest slot by cosine similarity (`max` over
        `cosine(normalized_vector, slot.centroid)`). **Tie-break
        divergence**: Python's `max(range(len(slots)), key=...)`
        (`centroids.py:116-119`) returns the **first** index on a tie;
        Rust's `Iterator::max_by` returns the **last**. Implement
        first-wins explicitly (manual `best_index`/`best_score` tracking
        with strict `>`, or `.enumerate().rev().max_by(...)`) and cover
        with the dedicated test in Testing item 11.
      - Merge: `slot.centroid = weighted_centroid(slot.centroid,
        slot.count, normalized_vector)`; `slot.count += 1`;
        `slot.learning_ids.push(new_learning_id)`
        (`centroids.py:120-123`); add to `seen_learning_ids`.
    - Materialize: for each `(slot_index, slot)` in
      `slots.into_iter().enumerate()`, build a `TruthCentroidPayload` with
      `slot: slot_index`, shared `dataset_id`/`truth_epoch`/`updated_at`,
      and the slot's `count`/`centroid`/`learning_ids`
      (`centroids.py:126-137`). The returned `slot` is the position in the
      rebuilt vector, not necessarily the original `.slot` value if the
      truncation step dropped entries — matches Python exactly.

11. **`centroids_changed`**. Port `centroids.py:140-162`: `true`
    immediately if `old.len() != new.len()`. Else index `old` by `.slot`;
    for each `new` centroid: `true` if no matching `old` slot, or `count`
    differs, or `centroid.len()` differs, or `learning_ids` differ
    (order-sensitive vector equality); else compare each paired
    `(old_value, new_value)` with `(old - new).abs() > tolerance` (default
    `1e-6`, `centroids.py:143`), `true` on first exceedance. `false`
    otherwise. **Ignores `truth_epoch`/`updated_at` entirely** — two
    centroid sets differing only by epoch/timestamp are "unchanged" (the
    invariant P2-03 relies on to skip a redundant re-upsert). Call this
    out explicitly; it's easy to assume epoch should matter.

12. **Do not port** `load_centroids`/`upsert_centroids`
    (`centroids.py:165-194`) — those need a live vector-engine trait
    object and belong to P2-03, which consumes `TRUTH_CENTROID_COLLECTION`
    (step 2) and the pure functions from steps 3–11.

13. Update `crates/truth-subspace/src/lib.rs`: `pub mod models;`, `pub mod
    centroids;`, and re-export `TruthCentroidPayload`, `centroid_id`,
    `learning_id`, `build_centroids_from_learning_vectors`,
    `extend_centroids_with_learning_vectors`, `centroids_changed`,
    `DEFAULT_K`, `TRUTH_CENTROID_COLLECTION` so downstream crates (P2-03,
    later hybrid-retriever wiring) don't reach into submodules.

## Parity notes

- **`centroid_id`**: `Uuid::new_v5(&Uuid::NAMESPACE_OID,
  format!("TruthCentroid:{dataset_id}:{slot}").as_bytes())` — exact string
  layout from `centroids.py:20-21`; bit-identical to Python for any
  `dataset_id` (no normalization either side).
- **`learning_id`**: raw uuid5 over `"TruthLearning:{normalized}"` where
  `normalized` = lowercase + whitespace-collapse (`centroids.py:24-26,197-198`).
  Accepted divergence: `.to_lowercase()` vs Python `.casefold()` on
  non-ASCII input. Returns `String`, not `Uuid`.
- **`data_point_id_for` is NOT reused** — checked
  `crates/utils/src/id_generation.rs:81-88`; it applies
  `normalize_identifier` (lowercase + space→`_` + strip apostrophes) per
  value before `|`-joining, which neither Python function does. Confirmed
  non-identical; both id functions here call `Uuid::new_v5` directly.
- **`DEFAULT_K = 8`** (`constants.py:3`) — slot capacity per dataset.
- **`TRUTH_CENTROID_COLLECTION`**: Python `"TruthCentroid_vector"`
  (`constants.py:1`) becomes Rust pair `("TruthCentroid", "vector")`,
  reconstructing to the same name via `format!("{data_type}_{field_name}")`.
- **`weighted_centroid`**: `(count*old + new)/(count+1)` per component,
  then L2-renormalized; empty `old` ⇒ just normalize `new`. Zip-truncates
  to the shorter input rather than erroring on length mismatch.
- **`normalize`**: zero vector stays all-zero, no panic (`centroids.py:32-33`).
- **`pad_coords`**: front-truncate then right zero-pad to `k`
  (`centroids.py:37-39`; e.g. `pad_coords([0.1,0.2], 4) ==
  [0.1,0.2,0.0,0.0]`, `pad_coords([0.1,0.2,0.3], 2) == [0.1,0.2]`, per
  `test_centroids.py:35-37`).
- **Nearest-slot tie-break divergence** (must guard with a test): Python
  `max(range(...), key=...)` is first-wins on ties; naive Rust `max_by` is
  last-wins. Implement first-wins explicitly.
- **`centroids_changed` ignores `truth_epoch`/`updated_at`** — only
  `count`, `centroid` (length + per-value `tolerance=1e-6`), and
  `learning_ids` (order-sensitive) participate (`centroids.py:140-162`).
- **Existing-slot truncation on rebuild**: sorts `existing_centroids` by
  `.slot`, keeps first `k` (`centroids.py:101`); any centroid with
  `.slot >= k` from a prior higher-`k` run is silently dropped, and
  returned payloads are re-indexed by rebuilt-list position, not original
  `.slot`. Pre-existing Python behavior, ported as-is.
- **Determinism**: same `dataset_id` + same ordered `learning_vectors` +
  same `k` ⇒ fully deterministic output regardless of
  `truth_epoch`/`updated_at` — the exact invariant
  `test_build_centroids_is_deterministic_for_same_inputs`
  (`test_centroids.py:68-74`) checks and this task's Rust tests must
  reproduce.
- **Acceptance bar for this task is unit-level**, not cross-SDK e2e (no
  BM25/retriever-facing surface here yet) — same algorithm, same
  constants, deterministic slot assignment matching the Python test
  suite's assertions below.

## Risks & open items

- **Casefold divergence**: `.to_lowercase()` vs Python `.casefold()` is an
  accepted gap for non-ASCII learning statements. Revisit if a future
  cross-SDK test compares Python- and Rust-computed `learning_id`s
  directly.
- **Tie-break semantics**: nearest-slot cosine tie-break (first-wins) is
  subtle and easy to regress; Testing item 11 is the main guard — any
  future refactor to a library `max_by`/`max_by_key` call must re-verify
  against that case.
- **Crate identity owned by P2-01**: this doc assumes the crate/package
  name follows the `cognee-<crate>` convention (e.g. `cognee-models`,
  `cognee-utils`) — assumed `cognee-truth-subspace`. If P2-01 names it
  differently, update all references here before implementing.
- **No wiring/I/O/callers yet**: `lib.rs` must `pub use` everything (step
  13) so public API surface isn't flagged as dead code despite zero
  internal callers.
- **`updated_at` default needs `chrono`**: confirm P2-01 already added
  `chrono.workspace = true` to `crates/truth-subspace/Cargo.toml`, or add
  it in this task if not.
